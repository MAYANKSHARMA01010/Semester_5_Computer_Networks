## Configuration and launch

Run the existing Phase 1 setup scripts for the primary edge and backends on Mac 2, Mac 3 and Mac 4. For restarting just a backend, use `bash phase1/scripts/helpers/mac3-start-backend.sh` or `bash phase1/scripts/helpers/mac4-start-backend.sh` in its own Terminal tab. Stop the backend via Ctrl+C in that tab. The primary NGINX config lives in [phase1/nginx/network-project.conf](../phase1/nginx/network-project.conf). Both upstreams are regular round-robin members. NGINX's passive failure accounting and upstream retry on connection errors or timeouts allow an eligible request to move to Backend B when A stops.

On each DNS server, keep a dedicated service tab. The repo's foreground DNS script is an alternative to the existing live services. Stop the current DNS instance on that Mac first so it releases UDP and TCP 53. For the rehearsal's Homebrew root service on Mac 1 use `sudo brew services stop dnsmasq`. For the existing foreground service on Mac 4 use Ctrl+C in its service tab. Check port ownership with `sudo lsof -nP -iUDP:53 -iTCP:53` if needed. Leave the foreground tab running.

| Mac | Normal launch from the repository root |
| --- | --- |
| Mac 1 · Aman | `bash phase2/scripts/dns.sh primary baseline 10.7.28.47 serve` |
| Mac 4 · Satyam | `bash phase2/scripts/dns.sh backup baseline 10.7.28.47 serve` |

The third argument is the separate TTL-test record's IP. Use the current primary edge IP if it has changed. For cutover, restart each server with `standby` in place of `baseline`. This changes only `app.team1.test`. Both modes use a TTL of 30 seconds and the same upstream forwarder, defaulting to `1.1.1.1`. Set `CN_DNS_FORWARDER` to an IPv4 resolver reachable from campus Wi-Fi if needed. Omit `serve` to print the configuration without touching the running service. On each designated client, run `bash phase2/scripts/client-dns.sh set` and save the resolver order. Use `client-dns.sh flush` for cold lookups and the manual-flush demo.

## TLS and standby edge

Primary TLS files are generated by the Phase 1 Mac 2 setup script under the Homebrew NGINX configuration directory. On Mac 2, copy the public certificate to a readable path with `sudo cat "$(brew --prefix)/etc/nginx/ssl/team1.crt" > "$HOME/Downloads/team1-primary.crt"`. On Mac 3, `bash phase2/scripts/standby.sh start` generates a public certificate and private key in `~/.cn-phase2-standby/`, validates the config and starts NGINX. Use `standby.sh stop` after restoring DNS. The old manual standby uses `~/.cn-standby/` and must release port 8443 before starting the scripted standby.

Verify certificate fingerprints with the edge owners using `openssl x509 -in PUBLIC_CERT.crt -noout -fingerprint -sha256`. Distribute the verified public certificates to demo clients. For curl, pass `--cacert` with the intended edge's public cert, or a concatenated primary and standby certificate bundle for cutover. For a browser demo, import the verified public cert into Keychain Access and set trust for SSL on each browser client. Keep private keys on their originating edge. Both certs must cover the requested domain in Subject Alternative Name. The scripts use certificate verification throughout.

## Firewall and restoration

On Mac 3 run `bash phase2/scripts/isolation.sh a apply`. On Mac 4 run `bash phase2/scripts/isolation.sh b apply`. These install dedicated PF anchors under the existing macOS `com.apple/*` filter anchor, retaining pre-demo status and the script's enable reference in the ignored runtime backup directory. During cutover only, on Mac 4 use `bash phase2/scripts/isolation.sh b apply standby` so Mac 3's standby can reach Backend B. After cutover run `isolation.sh b apply primary` on Mac 4 to remove that temporary source. On both Macs use their respective `restore` actions after the complete demonstration to remove the project rules and release their PF enable references.

The rehearsal's existing anchors were installed manually. Before adopting the scripted PF workflow, use the live rehearsal's original state and release tokens as described in the [evidence checklist](../evidence/README.md#restore-the-original-pf-state). The scripted restore only manages PF changes made through the script.
